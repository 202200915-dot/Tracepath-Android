# Tracepath — Android app (Capacitor)

This wraps the existing Tracepath PWA (unchanged) into a real, installable
Android app using **Capacitor**. Nothing about the app itself was rebuilt or
redesigned — `www/` is the same HTML/CSS/JS from the PWA, plus one small,
guarded script (see "What actually changed" below).

## Why Capacitor (not Trusted Web Activity)

Tracepath is a static, no-build PWA with no live HTTPS deployment. A
Trusted Web Activity (Bubblewrap) needs the PWA hosted at a public HTTPS URL
with a Digital Asset Links file, or Android shows a browser address bar
instead of a real app. Capacitor instead bundles the existing web files
straight into the APK and runs them in a WebView under `https://localhost`,
so it works completely offline, needs no hosting, and required no changes to
your HTML/CSS/JS structure — just wrapping.

## ⚠️ About the .apk file itself

I could not compile the actual `.apk` binary in this sandbox: building an
Android app requires downloading the Android Gradle Plugin and Android SDK
components from Google's Maven repo, and the Gradle distribution from
`services.gradle.org` — this sandbox's network is locked to a small allow-list
(npm, PyPI, GitHub, etc.) that doesn't include those, and I confirmed all
three return `403` when the build tries to reach them.

What you have instead is the **complete, real, ready-to-build native Android
project** — generated by the official Capacitor CLI (not hand-written by
guesswork) and customized with Tracepath's branding, icons, splash screen,
and Android back-button handling. Getting the actual `Tracepath.apk` from
here takes one of the two paths below, and doesn't require you to know
Android development.

## Path A — GitHub Actions (no Android Studio needed)

1. Push this whole folder to a new GitHub repo.
2. GitHub Actions builds automatically on every push (workflow file already
   included at `.github/workflows/build-apk.yml`), or trigger it manually
   from the repo's **Actions** tab → "Build Tracepath APK" → **Run workflow**.
3. When it finishes, open the workflow run → **Artifacts** → download
   **Tracepath-debug** (a zip containing `Tracepath-debug.apk`). It's signed
   with the Android debug key, so it installs immediately for testing.
4. For a proper release build (`Tracepath.apk`, signed with your own key),
   see "Signing a release build" below — once you add the four secrets it
   asks for, the same workflow also produces and uploads `Tracepath`.

## Path B — Build locally with Android Studio / command line

**Requirements:** Node.js 18+, JDK 17, and the Android SDK (installed
automatically if you use Android Studio — download from
developer.android.com/studio).

```bash
npm install
npx cap sync android
cd android
./gradlew assembleDebug          # -> app/build/outputs/apk/debug/app-debug.apk
```

That debug APK is installable right away. Copy it to your phone (or
`adb install app/build/outputs/apk/debug/app-debug.apk` with the phone
connected and USB debugging on).

Alternatively, open the `android/` folder directly in Android Studio and hit
**Run**, or **Build → Generate Signed Bundle / APK**.

### Signing a release build

An Android release build must be signed. To get a real, installable
`Tracepath.apk`:

```bash
cd android
keytool -genkeypair -v -keystore tracepath-release.jks -alias tracepath \
  -keyalg RSA -keysize 2048 -validity 10000
cp keystore.properties.example keystore.properties
# edit keystore.properties: fill in the store/key passwords you just set
./gradlew assembleRelease         # -> app/build/outputs/apk/release/app-release.apk
```

**Keep `tracepath-release.jks` and its passwords safe** — every future
update to this app must be signed with the same key, or Android will refuse
to install it as an upgrade. `keystore.properties` and `*.jks` are already
git-ignored, so they won't accidentally get committed.

To let GitHub Actions build the signed release for you instead, add these
four **repository secrets** (Settings → Secrets and variables → Actions):
- `KEYSTORE_BASE64` — output of `base64 -w0 tracepath-release.jks` (or
  `base64 -i tracepath-release.jks` on macOS)
- `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` — matching what you used
  in `keytool`

## What actually changed vs. the original PWA

Nothing in the app's behavior, data, or design — only Android-packaging
additions, all isolated so they don't affect the web version at all:

- `www/js/android-bridge.js` (new file, ~40 lines) — maps the hardware back
  button to in-app navigation (closes an open dialog/sheet first, then steps
  back through the hash-based screens, then asks for a second press to exit
  from the home screen). It checks `window.Capacitor` first and does nothing
  at all when the app is opened as a normal web page or installed PWA.
- One added `<script>` tag in `www/index.html` loading that file.
- `android/` — the native project itself (icons, splash screen, app name,
  package ID, theme colors), generated by `npx cap add android` and then
  branded to match Tracepath (`css/styles.css` tokens and the existing
  `icons/icon-512.png` / `icons/maskable-512.png`).

Everything else in `www/` — `index.html`'s markup, `css/styles.css`,
`js/app.js`, `js/data.js`, `js/i18n.js`, `js/resources.js`, `sw.js`,
`manifest.webmanifest`, fonts, icons — is byte-for-byte what was in the
uploaded project.

## Data, offline behavior, and RTL — unaffected

- **LocalStorage / progress / settings**: Capacitor's WebView keeps its own
  persistent storage per app install, exactly like a browser keeps it per
  site — nothing about how `js/app.js` reads/writes `localStorage` changed.
- **Service worker / offline cache**: `sw.js` only registers under `http(s)`
  (see `js/app.js`'s existing protocol check), which is why
  `capacitor.config.json` sets `"androidScheme": "https"` — the app runs at
  `https://localhost`, so the same service-worker code path activates and
  precaches the app shell exactly as it does in a browser.
- **English/Arabic + RTL**: pure CSS/JS in `js/app.js` and `js/i18n.js`,
  untouched — works identically inside the WebView.

## Verifying the result

Once you have a built APK (either path above), install it on an Android 8+
device and check: app icon and name, Today/Roadmap/Academy/Projects/
Certs/Settings screens, language switch + RTL mirroring, adding/rating/
bookmarking a resource, export/import backup, offline mode (enable airplane
mode after first launch), and the hardware back button (steps back through
screens, then asks for a second press to exit from Today).
